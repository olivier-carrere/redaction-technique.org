## How this site is built

This site deals with technical writing processes and formats, so its [history and Git branches](https://github.com/olivier-carrere/redaction-technique.org/) are as relevant as its content.

It covers the following formats, tools, and tasks: reStructuredText, DITA XML, Bash scripts, awk, sed, regular expressions, Python, version control, Git, compilation, Makefile, Ant, XSLT, layout, HTML, CSS, PDF, LaTeX, XSL-FO.

Today, the portfolio is written in MDX and built with Astro and Starlight. GitHub Actions builds it on every push and pull request, a test suite checks its content and API, and it is published in English and French. The same sources also feed a [machine-readable API](/en/about-the-api/) and a grounded [documentation assistant](/en/ask/).

### This site's sources are managed under Git

This site was initially developed under WordPress. The inability to make cross-cutting changes or to have precise tracking of the content lifecycle under this <abbr title="Content Management System">CMS</abbr> led to a migration to the lightweight markup format reStructuredText.

![](/assets/documentation-life-cycle-framework.webp)

All versions of this site are managed under the decentralized version control software Git. Content, structure, or layout changes can now be:

- grouped into coherent batches,
- linked to a ticket in an issue tracker such as *Bugzilla* or *Jira*,
- validated by peers,
- shared between different versions of the documentation project,
- undone in a single operation, etc.

## Free your information from its silos

Flexible and reliable solutions free your information from siloed repositories where it is imprisoned and underutilized. Move beyond MS Word or FrameMaker to shift from documentation maintenance to managing the lifecycle of modular documentation projects.

### [Integrate documentation into the development process](/en/tech-writing-process/integrating-documentation-into-development/)

Documentation is part of the software. Delivered with the product, it must:

- ship at the same time,
- follow the same life cycles, and
- be subject to the same production and quality control processes.

<DevPipelineIntegrationDiagram />
**Modular documentation sources in text format**

Ideally, it should meet the following criteria:

- no *vendor lock-in* (independence of format and content editor),
- free and open-source publishing chains,
- fully automated layout.

Not so long ago, the only tools capable of delivering quality PDF or HTML output relied on binary and proprietary formats that integrated poorly with development teams' version control systems.

As a result, technical documentation was produced separately and struggled to meet the same quality and time-to-market requirements as the products themselves.

DocBook, then DITA XML and reStructuredText changed the game: these text formats can be edited with any type of program, from a simple text editor to a graphical <abbr title="Integrated Development Environment">IDE</abbr>, and integrate perfectly with Subversion, Git, or any other version control system.
