Docs-as-code is not just storing documentation in Git. It is an engineering workflow: documentation is written in text-based source formats, kept in version control next to the product, changed on branches, reviewed through pull requests, checked automatically, and published by a pipeline. This section follows the order in which a team usually adopts it: why, Git, repository design, branches, then CI/CD and review.
