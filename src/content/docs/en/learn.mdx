## How the rest of this manual builds on them

The sections that follow form a progression. Documentation is only as maintainable as its structure, so [structured information](/en/tools-and-formats/) and [modular content](/en/formats/modular-documentation/) come first. Modular text sources can be managed in [Git](/en/docs-as-code/) like code, which makes automation and [CI/CD](/en/toolkit/example-cicd-pipeline/) possible. Content that is structured and built automatically can then also be published in [machine-readable form](/en/about-the-api/), for scripts, search systems, and AI assistants as well as human readers.

Once these foundations click, move on to [building a documentation process](/en/process/) or jump straight to the [practical toolkit](/en/toolkit/) for templates and checklists. For the foundational format choice, see [choosing an authoring model](/en/tools-and-formats/). For unfamiliar terms, see the [glossary](/en/reference/glossary/).
