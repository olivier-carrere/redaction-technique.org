## Definition

The <abbr title="Content Management System">CMS</abbr>, often termed this way for marketing purposes but more accurately described by the acronym <abbr title="Electronic Document Management System">EDMS</abbr>, introduces workflow and link management features that are invaluable for handling modular documents.

## Key principles

When using monolithic formats such as FrameMaker, technical writers can employ a CMS like SharePoint, Alfresco, or similar systems (as an alternative to a [single Git repository](../single-repository/)) to:

1. download a local copy of shared files to their hard disk,
2. make modifications to the local copy,
3. upload the modified copy to the central repository.

This approach is more efficient than using a simple file server, primarily because file transfers over the network are less frequent. However, it remains necessary to lock files being modified, a task managed by the CMS.

While originally designed for monolithic documents, many CMS solutions now accommodate the modularization of technical documentation. Systems such as DocZone or Componize, the latter built on Alfresco, are specifically designed to manage [modular documentation](../../formats/modular-documentation/) using the DITA XML architecture.

## Trade-offs

How can we be sure that solutions updated this often — frequently for commercial rather than technical reasons — stay consistently reliable?

It's prudent to exercise caution when relying entirely on them for managing and archiving documentation source files. A careful selection of the solution is essential, paired with a robust backup and restore strategy.

## The docs-as-code alternative

With text-based source formats, a version control system provides most of what a CMS workflow is chosen for, without file locking: branches let several writers work in parallel, pull requests carry the review and approval steps, and the history records who changed what and when. Every clone of a Git repository is also a full copy of its history, which addresses part of the archiving concern. See [integrating documentation into development processes](../integrating-documentation-into-development/) and the [review workflow example](../../toolkit/example-review-workflow/).

A CMS remains relevant when contributors cannot work with text files and version control, or when the organization already relies on one for other content.
