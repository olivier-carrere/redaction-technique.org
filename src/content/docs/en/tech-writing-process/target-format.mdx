## Definition

The target format for technical writing is the medium through which the audience will access the content. This is distinct from the [source format](../source-format/) in which the technical writer initially creates the content. The *single-sourcing* process allows multiple deliverables in various formats to be generated from a single source format.

The more automated the process, the lower the risk of error, and the easier it is to publish and update. Automation also facilitates *single-sourcing*, enabling the generation of multiple deliverables in different target formats from the same source format. A project in DITA XML format can be delivered as a PDF file, Windows compiled help, JavaHelp, an HTML site, and more — the [formats and tools](../../costs/formats-and-tools/) article explains how the choice of format shapes these possibilities. In this regard, XML offers nearly unlimited possibilities.

Lightweight formats follow the same principle. In a docs-as-code workflow, Markdown sources are typically built by a static site generator into an HTML site, and publishing is a pipeline step rather than a manual one (see [delivery](../delivery/)). Target formats are no longer only for human readers: this manual is generated from Markdown into HTML pages, and also into per-page Markdown files and JSON indexes for scripts and AI assistants (see [about this manual's API](/en/about-the-api/)).
