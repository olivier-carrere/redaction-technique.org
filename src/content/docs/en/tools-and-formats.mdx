The decisions that shape everything else: how much formal structure your content needs, how to reuse it, which source format to write in, and which target formats to publish to.

Structured content principles (separating content from presentation, typing information by reader intent, writing reusable modules) apply to almost every documentation project. What varies is how strictly they are enforced. DITA XML enforces them through a schema and a dedicated toolchain; Markdown in a docs-as-code workflow applies them by convention, templates, and automated checks. Neither is obsolete: different projects need different levels of formal structure.
