Le docs-as-code ne se résume pas à stocker la documentation dans Git. C'est un workflow d'ingénierie : la documentation est rédigée dans des formats source texte, conservée sous gestion de versions à côté du produit, modifiée dans des branches, relue par pull request, vérifiée automatiquement et publiée par un pipeline. Cette section suit l'ordre dans lequel une équipe l'adopte généralement : pourquoi, Git, conception du référentiel, branches, puis CI/CD et revue.
