Les décisions qui conditionnent tout le reste : le degré de structure formelle dont votre contenu a besoin, la manière de le réutiliser, le format source dans lequel rédiger et les formats cibles vers lesquels publier.

Les principes du contenu structuré (séparer le fond de la forme, typer l'information selon l'intention du lecteur, rédiger des modules réutilisables) s'appliquent à presque tous les projets documentaires. Ce qui varie, c'est la rigueur avec laquelle ils sont imposés. DITA XML les impose par un schéma et une chaîne d'outils dédiée ; le Markdown, dans un workflow docs-as-code, les applique par convention, par des modèles et par des contrôles automatisés. Aucune des deux approches n'est obsolète, et aucune n'est supérieure dans l'absolu : chaque projet appelle un niveau de structure formelle différent.
